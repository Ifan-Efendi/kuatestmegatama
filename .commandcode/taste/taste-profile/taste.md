# Taste Profile
- Prefers to use their own hosting/deployment solution and wants pre-configured platform files (e.g., wrangler.toml, vercel.json, netlify.toml) removed from projects. Confidence: 0.85
- Prefers to communicate in Indonesian. Confidence: 0.9
- Prefers phone numbers formatted with hyphens as separators (e.g., `08-9534-4573-716`, `62-811-2224-624`). Confidence: 0.7
- Values layout consistency between analogous page types — when implementing a feature, reuses the pattern already established on a similar page (e.g., product listings mirror article listings: sidebar right, pagination at bottom; related products section mirrors recent posts layout from article pages). Confidence: 0.85
- On mobile, sidebar/filter/search widgets should appear above the main content (via `order-first`), while on desktop they remain on the right side. Confidence: 0.7
- Prefers contact info in footers (phone numbers, email) stacked vertically rather than laid out horizontally side by side. Confidence: 0.6
- Expects visual uniformity among sibling elements within the same UI group — items in the same list, column, or section should share identical styling (color, font weight, hover behavior, icon pattern, heading size, image height, etc.). When one element looks off, they will flag it. Confidence: 0.85
- Prefers SVG icons sourced from established, professional icon libraries (e.g., Font Awesome) rather than AI-generated or approximated paths. Values precise, polished icon shapes and will reject icons that look "AI-generated" or sloppy. Confidence: 0.7
- Prefers Title Case capitalization (Huruf Awalan Kapital) for Indonesian website copy such as taglines, descriptions, and marketing text — each major word starts with a capital letter. Confidence: 0.65
- Expects exhaustive replacements — when asked to change text (names, addresses, descriptions, etc.), all occurrences across every file type and content directory must be found and replaced in one pass. Will spot missed instances and ask for verification. Confidence: 0.7
- When adapting section content for a different domain/industry, prefers to keep the existing structure and layout intact — only the copy/text should change, not the arrangement of elements. Confidence: 0.7
- Prefers contact/order forms that redirect to WhatsApp with a pre-filled structured template message rather than submitting via email, API, or server-side providers (e.g., Netlify Forms, Formspree). The WhatsApp number and message format should be hardcoded into the form script. Confidence: 0.8
- When asked to add or change a section/feature, defaults to editing existing components and content files rather than creating entirely new ones (new schemas, new `.astro` files, new content entries). Only create from scratch when the existing structure genuinely cannot accommodate the request. Confidence: 0.7
- Expects changes to be safe and reversible — when a set of changes breaks things or the user is dissatisfied, they expect a clean, complete rollback of all modified files to their original state (via `git checkout`). Undo requests are often scoped to a specific feature (e.g., "undo semua yang mitra") and expect exactly that feature's changes reverted — including deletion of newly created components, copied assets, and folders — without disturbing unrelated work. Confidence: 0.8
- Prefers authentic brand logos for brand-specific features — when a button or link represents a specific platform (e.g., WhatsApp, Facebook, Instagram), the user expects that platform's actual recognizable logo, not a generic proxy icon (e.g., using a phone icon for WhatsApp). Confidence: 0.75
- Avoids HTML number input spinners (`type="number"`) for quantity/count fields — prefers `type="text"` with `inputmode="numeric"` and `pattern="[0-9]*"` so users type the number directly without a scroll-based spinner widget. Confidence: 0.8
- Physical addresses anywhere on the site (contact sections, footers, etc.) should be clickable hyperlinks that open Google Maps (using `https://maps.google.com/?q=...` search query) so visitors can directly navigate to the location. Confidence: 0.85
- Prefers form fields with visible labels placed above the input (vertical layout: label on top, input below), rejecting hidden-label or placeholder-only form designs. Confidence: 0.85
- Dislikes thin divider/separator lines between UI elements AND unwanted white-space blocks from bottom padding/margins — prefers clean, tight spacing over explicit `border-t`, `divide-x`, `divide-y` separators or loose `py-*`/`section-spacing-vertical` padding that leaves visible white gaps. Will flag and ask for their removal. Confidence: 0.75
- Values project independence from original upstream sources — when working on a project cloned or derived from a third-party template/theme, wants Git remotes updated to point to their own repository and is concerned about lingering ties to the original author's account. Confidence: 0.85
- Prefers to remove AI assistant/editor configuration files for tools not in active use (e.g., `.cursor/`, `.windsurf/`, `CLAUDE.md`, `GEMINI.md`, `SKILLS.md`), keeping only those relevant to their current toolchain. Confidence: 0.75
- Prefers website copy to be concise, short, and direct ("singkat, jelas, padat") — avoids verbose or wordy text on the basis that visitors don't want to read too much. The "Tentang" (About) section is the explicit exception where more detailed content is welcome. Confidence: 0.85
- Expects pages to render without horizontal overflow — no horizontal scrollbars, no white space on the right side of the viewport. The page must fit the window width exactly with no content spilling into an invisible overflow area. Will flag any visible right-side white space as unacceptable. Confidence: 0.8
- Prefers CTA/contact button labels that describe the value or action the visitor receives (e.g., "Konsultasi," "Konsultasi Gratis," "Konsultasi Sekarang") rather than generic contact labels like "Hubungi Kami." Positions the interaction as a benefit-driven consultation, not just a generic contact. Confidence: 0.2
- Values modern, clean, and polished visual design — explicitly asks for the site to look "better and more modern," favoring refined typography, unified cards/surfaces, and tighter modern styling over default template aesthetics. Will flag a navbar/menu that renders "jelek" (ugly) and expect it fixed. Confidence: 0.7
- Communicates desired UI layouts by sharing reference screenshots/images and expects the implementation to match the reference's layout and button placement. Confidence: 0.6
- Expects feature parity across responsive breakpoints — when a header/navigation feature (e.g., product search) is added for desktop, the same capability should also be available on mobile (e.g., inside the offcanvas menu), not just on one viewport. Confidence: 0.7
- Resumes interrupted/prior sessions by pasting a transcript or screenshot of the earlier chat and expects the assistant to re-inspect the current file state and continue the unfinished work rather than assume the previous pass is complete. Confidence: 0.6
- On mobile, prefers search to be presented as a compact icon-only control (e.g., a magnifying-glass icon) placed beside the hamburger button rather than a full-width search input/form taking up navbar space. Confidence: 0.6
- Prefers minimal, uncluttered navigation menus — when simplifying a navbar/offcanvas, strips non-essential elements (social media links, logo, CTA buttons like "Lihat Katalog"/"Konsultasi", search) and keeps only the menu items, explicitly valuing a simple ("simpel") look. Confidence: 0.75
- On mobile, prefers a compact header — the logo mark and wordmark should be visibly smaller than desktop (e.g., reduced logo height and font-size at tablet/mobile breakpoints) to keep the navbar space-efficient and simple. Confidence: 0.6
- When a section's photo/image needs changing, the user points to the target section via a screenshot and then uploads their own replacement image file(s) in a follow-up message, expecting the assistant to copy them into the project's public assets (with clean filenames) and update the relevant content reference rather than sourcing a stock or placeholder image. Confidence: 0.6
- Prefers headings/titles to be split into explicit line breaks at chosen points (e.g., brand name on its own line, tagline/descriptor on the next) rather than flowing as a single continuous line, and communicates the exact break point ("after X, new line"). Confidence: 0.5
- When asked to replace images (e.g., partner/client logos), prefers keeping the existing card/section structure and layout untouched with card sizes fixed. "Jangan dihapus" (don't delete) means the card should still carry a text label and a logo rather than be left empty, but the content may be adapted — e.g., swapping a generic service title for the actual partner/company name and a service icon for the partner logo — not only the image itself. Confidence: 0.8
- Wants replaced images (especially partner/client logos) sized and normalized so they render neat and uniform — properly contained (e.g., `object-contain`, constrained height) rather than stretched, distorted, or inconsistently sized. Confidence: 0.6
- When handing over replacement images, may point to an existing folder inside the project (e.g., a `mitra/` folder) where the source files live, expecting the assistant to locate them, copy them into public assets with clean filenames, and reference them — not only via direct uploads. Confidence: 0.55
- When listing partner/client logos, prefers to display all of them (e.g., via a scrolling marquee/carousel) rather than truncating to a subset that happens to fit the current layout. Confidence: 0.55
- When modifying or replacing a section/card, expects existing hover interactions to be preserved rather than dropped — e.g., the blue gradient overlay that rises over the card on hover should be restored/replicated to match the original design. Confidence: 0.6
- Prefers icons that semantically match the entity they label — e.g., a building icon for companies/PT and a graduation-cap icon for universities/campuses — rather than a single generic icon across mixed entity types. Confidence: 0.6
- For partner/client logo cards, ultimately prefers a minimal card containing only the logo image and its name — no supplementary service icons (building/graduation-cap) or other decorative elements. Confidence: 0.6
- Prefers dark blue (biru tua / theme-dark) as the hover state color for interactive/CTA elements like "Baca Selengkapnya" buttons/links — dark blue background with white text and a matching border, rather than the theme's primary/accent color. Confidence: 0.6
- Uses GitHub for version control and expects the assistant to commit and push completed changes to the remote when asked (e.g., "push ke github"). Confidence: 0.6
- When adapting a template/site to the client's actual domain, expects placeholder/demo content to be rewritten across every content collection — including blog articles (e.g., software/tech posts rewritten into civil-engineering lab-testing posts), not just product names or section copy — and will follow up to flag remaining content types still carrying the old domain. Confidence: 0.6
