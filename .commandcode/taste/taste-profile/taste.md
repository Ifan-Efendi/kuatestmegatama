# Taste Profile
- Prefers to use their own hosting/deployment solution and wants pre-configured platform files (e.g., wrangler.toml, vercel.json, netlify.toml) removed from projects. Confidence: 0.85
- Prefers to communicate in Indonesian. Confidence: 0.9
- Prefers phone numbers formatted with hyphens as separators (e.g., `08-9534-4573-716`, `62-811-2224-624`). Confidence: 0.7
- Values layout consistency between analogous page types — when implementing a feature, reuses the pattern already established on a similar page (e.g., product listings mirror article listings: sidebar right, pagination at bottom; related products section mirrors recent posts layout from article pages). Confidence: 0.85
- On mobile, sidebar/filter/search widgets should appear above the main content (via `order-first`), while on desktop they remain on the right side. Confidence: 0.7
- Prefers contact info in footers (phone numbers, email) stacked vertically rather than laid out horizontally side by side. Confidence: 0.6
- Expects visual uniformity among sibling elements within the same UI group — items in the same list, column, or section should share identical styling (color, font weight, hover behavior, icon pattern, heading size, image height, etc.). When one element looks off, they will flag it. Confidence: 0.85
- Prefers SVG icons sourced from established, professional icon libraries (e.g., Font Awesome) rather than AI-generated or approximated paths. Values precise, polished icon shapes and will reject icons that look "AI-generated" or sloppy. Confidence: 0.7
- Prefers Title Case capitalization (Huruf Awalan Kapital) for Indonesian website copy such as taglines, descriptions, and marketing text — each major word starts with a capital letter. Confidence: 0.65
- Expects exhaustive replacements — when asked to change text (names, addresses, descriptions, etc.), all occurrences across every file type and content directory must be found and replaced in one pass. Will spot missed instances and ask for verification. Confidence: 0.7
- When adapting section content for a different domain/industry, prefers to keep the existing structure and layout intact — only the copy/text should change, not the arrangement of elements. Confidence: 0.7
- Prefers contact/order forms that redirect to WhatsApp with a pre-filled structured template message rather than submitting via email, API, or server-side providers (e.g., Netlify Forms, Formspree). The WhatsApp number and message format should be hardcoded into the form script. Confidence: 0.8
- When asked to add or change a section/feature, defaults to editing existing components and content files rather than creating entirely new ones (new schemas, new `.astro` files, new content entries). Only create from scratch when the existing structure genuinely cannot accommodate the request. Confidence: 0.7
- Expects changes to be safe and reversible — when a set of changes breaks things or the user is dissatisfied, they expect a clean, complete rollback of all modified files to their original state (via `git checkout`). Confidence: 0.75
- Prefers authentic brand logos for brand-specific features — when a button or link represents a specific platform (e.g., WhatsApp, Facebook, Instagram), the user expects that platform's actual recognizable logo, not a generic proxy icon (e.g., using a phone icon for WhatsApp). Confidence: 0.75
- Avoids HTML number input spinners (`type="number"`) for quantity/count fields — prefers `type="text"` with `inputmode="numeric"` and `pattern="[0-9]*"` so users type the number directly without a scroll-based spinner widget. Confidence: 0.8
- Physical addresses anywhere on the site (contact sections, footers, etc.) should be clickable hyperlinks that open Google Maps (using `https://maps.google.com/?q=...` search query) so visitors can directly navigate to the location. Confidence: 0.85
- Prefers form fields with visible labels placed above the input (vertical layout: label on top, input below), rejecting hidden-label or placeholder-only form designs. Confidence: 0.85
- Dislikes thin divider/separator lines between UI elements AND unwanted white-space blocks from bottom padding/margins — prefers clean, tight spacing over explicit `border-t`, `divide-x`, `divide-y` separators or loose `py-*`/`section-spacing-vertical` padding that leaves visible white gaps. Will flag and ask for their removal. Confidence: 0.75
- Values project independence from original upstream sources — when working on a project cloned or derived from a third-party template/theme, wants Git remotes updated to point to their own repository and is concerned about lingering ties to the original author's account. Confidence: 0.85
- Prefers to remove AI assistant/editor configuration files for tools not in active use (e.g., `.cursor/`, `.windsurf/`, `CLAUDE.md`, `GEMINI.md`, `SKILLS.md`), keeping only those relevant to their current toolchain. Confidence: 0.75
- Prefers website copy to be concise, short, and direct ("singkat, jelas, padat") — avoids verbose or wordy text on the basis that visitors don't want to read too much. The "Tentang" (About) section is the explicit exception where more detailed content is welcome. Confidence: 0.85
- Expects pages to render without horizontal overflow — no horizontal scrollbars, no white space on the right side of the viewport. The page must fit the window width exactly with no content spilling into an invisible overflow area. Will flag any visible right-side white space as unacceptable. Confidence: 0.8
- Prefers CTA/contact button labels that describe the value or action the visitor receives (e.g., "Konsultasi," "Konsultasi Gratis," "Konsultasi Sekarang") rather than generic contact labels like "Hubungi Kami." Positions the interaction as a benefit-driven consultation, not just a generic contact. Confidence: 0.2
